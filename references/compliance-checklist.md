# 合规检查清单

> 读取时机：Phase 4 验证环节。在自动验证脚本通过后使用。
> 自动验证脚本只检查结构/格式，本清单检查**判断质量**——脚本无法自动化的部分。

---

## A. Frontmatter 质量

- [ ] `name` 是 kebab-case，不超过 64 字符
- [ ] `name` 与目录名一致
- [ ] `description` 不超过 500 字符（平台硬限制 1024）
- [ ] `description` 包含完整结构：WHAT / CAPABILITY / TRIGGERS / SLASH_CMD / NOT
- [ ] `description` 包含触发词（TRIGGERS：合并了原 WHEN，含口语表达、中英文、缩写、系统名词、命令斜杠等）
- [ ] `description` 包含明确指令（SLASH_CMD：/xxx 格式，说明直接触发时的行为）
- [ ] `description` 必须包含 TRIGGERS 与 NOT 条件（缺失任一项视为不合规）
- [ ] `description` NOT 用顿号分隔不触发场景
- [ ] `description` 没有 Stage 0 论证（那属于正文开头段落）
- [ ] `description` "略带攻击性"——宁可多触发也不要漏触发

### Description 测试

读 description 然后问自己：
1. "如果我是 agent，看到这段描述，我知道**什么时候该用**吗？"
2. "我知道**什么时候不该用**吗？"
3. "触发词（TRIGGERS）是否覆盖了口语表达、中英文变体等用户所有可能的触发说法？"
4. "明确指令（SLASH_CMD）是否可直接触发并进入流程？"

如果任一答案为"否"，重写 description。

---

## B. 正文结构

- [ ] 正文有模式要求的必需章节（按 P1-P5 不同）
- [ ] 正文包含 `## 诚实边界`（说明能力上限与信息不足时降级策略）
- [ ] 包含 Phase 1.5 与 Phase 2.5 的检查点输出约束
- [ ] 章节间无重复内容
- [ ] 没有 `## When to Use`（已由 description 覆盖）
- [ ] 没有 `## Anti-Patterns`（已由 description 的 NOT 覆盖）
- [ ] SKILL.md 不超过 500 行；超过时拆分到 references/
- [ ] 资源引用有"何时读取"列

---

## C. 指令具体性

对每个步骤/规则，检查：

- [ ] 动词是否具体？（"用 ImageMagick convert -resize 800x600" vs "处理图片"）
- [ ] 有明确的输入/输出吗？
- [ ] 有具体的参数/格式/示例吗？
- [ ] 没有模糊的"适当处理"、"合理设置"

### 模糊动词替换表

| 模糊 | 具体 |
|------|------|
| "处理图片" | "用 ImageMagick `convert -resize 800x600`" |
| "验证格式" | "检查输出是否匹配 JSON Schema：{schema}" |
| "适当调整" | "将长度超过 80 字符的行截断并加省略号" |
| "分析结果" | "提取 status 字段，若为 error 则进入异常处理流程" |

---

## D. 异常处理

- [ ] 每个可能失败的步骤有 fallback
- [ ] 失败处理是具体的（不是"处理错误"）
- [ ] 有用户确认的检查点
- [ ] 依赖缺失时有前置检查
- [ ] 输入缺失时有“先追问再执行”规则（under-spec 防护）

### 检查点设计原则

| 类型 | 示例 |
|------|------|
| 用户决策 | "发现 3 种方案，等用户选择" |
| 数据确认 | "生成的 SQL 如下，确认后执行" |
| 依赖检查 | "jq 未安装，是否继续？功能将受限" |

---

## E. 安全检查（公开发布红线）

> S001-S004 规则定义唯一权威：[SKILL.md](../SKILL.md) Step 1.3（红线表与环境变量方案）；本清单仅作逐项检查消费，不重复规则文本。

### E1. 硬编码安全（阻塞项 — 违反即禁止发布）

- [ ] **S001** 无硬编码密钥/Token/私钥/Secret
- [ ] **S002** 无硬编码内网 IP/域名（`10.x.x.x`、`172.16-31.x.x`、`*.internal.example.com`）
- [ ] **S003** 无硬编码数据库连接串（`mysql -h`、JDBC URL、`Host: IP:Port`）
- [ ] 所有外部连接均使用环境变量 `${VAR}` 或 `.env` 配置

### E2. 环境变量方案（涉及外部服务时必须）

- [ ] 存在 `.env.example` 文件，含所有配置项的占位说明
- [ ] SKILL.md 中有"前置检查"步骤，检查 `.env` 是否存在
- [ ] `.env` 缺失时有明确提示或用 AskQuestion 询问用户

### E3. 操作安全（AI 红线）

- [ ] **S004** 破坏性操作（`DELETE`/`DROP`/`TRUNCATE`/`rm -rf`/`git push --force`）有明确安全防护声明
- [ ] 危险操作前有用户确认步骤（不可静默执行）
- [ ] 输入验证有 sanitize 逻辑（SQL 注入、路径遍历等）

### E4. 数据安全

- [ ] 涉及敏感数据（手机号/身份证/地址/银行卡）时有脱敏说明
- [ ] 输出中不暴露完整敏感信息（遵循最小暴露原则）
- [ ] 日志/报告中敏感字段已脱敏

### 安全检查判定

- 命中 E1 任一项 → **阻塞**，必须修复后才能通过验证
- E2 缺失且涉及外部服务 → **阻塞**
- E3/E4 缺失 → **警告**，建议修复
