# 后置精炼手册（Refinement Playbook）

> 读取时机：Phase 5。  
> 目标：在不改变核心用途前提下，提升可执行性与稳定性。

## 适用范围

- 仅用于 Phase 4 已通过后的版本。
- 仅接受可归因、可验证的改动。
- 禁止“顺手重构”与无证据改写。

## 双评审流程

### Reviewer A（结构与协议）

关注点：
- 阶段契约是否完整（0-6 + 1.5/2.5）
- 输出模板是否可执行
- 异常路径是否可判定

输出格式：

```markdown
## Reviewer A
- 问题：{具体问题}
- 证据：{文件/段落}
- 改法：{可执行文本}
- 预期收益：{一句话}
```

### Reviewer B（评测与触发）

关注点：
- 是否存在 over-trigger/under-spec 风险
- 断言是否可验证
- description 的 WHEN/NOT 是否覆盖真实输入

输出格式与 Reviewer A 相同。

## 合并规则

- 两位评审建议不冲突：直接合并。
- 冲突：保留更保守方案，并记录舍弃理由。
- 每轮最多合并 3 条改动，防止过改。

## 回归验证

每次精炼后必须重跑：

```bash
python3 "${SKILL_ROOT}/scripts/validate_skill.py" <skill-path>
```

（`SKILL_ROOT` 定义见 SKILL.md 开头「路径约定」）

并补充以下最小回归检查：
- `over-trigger` 用例至少 1 条
- `under-spec` 用例至少 1 条
- 交付摘要字段完整（Skill/模式/验证/评测）

## 退出条件

- 连续两轮改动无评分收益，停止精炼。
- 已达到“可执行且可验收”，停止追求文本美化。
